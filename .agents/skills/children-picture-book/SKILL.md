# 電子兒童繪本

每本書重新依本次要求設定。不要把範例、上一本書或工具程式內的固定值當成新書需求。
把故事編輯、插畫設計、出版排版、閱讀驗證當成同一項工作，完成使用者已要求的成品。

## 先判斷此次工作

- **新書**：建立新的需求表與專案。適讀年齡、主題、情節、角色、字目、篇幅及風格均重新設定；只有使用者明確說「沿用」的項目才承接上一案。
- **修訂既有書**：先讀該書的需求、故事與排版來源，保留已接受的設定，只修改本次要求及其必須同步的部分；不要重新索取已知資料。
- **使用者供稿**：保留原文與版本，未授權改寫時只做指定的插畫、校對或排版。
- **知識繪本／改編**：先處理事實來源或原稿邊界，再設計敘事；不要把想像或推測當成知識。

## 工作流程

1. **收集本次需求。** 從最新指示與這一本書已確認的資料填寫需求表。至少釐清適讀年齡、閱讀方式、主題、內容任務及交付格式。只問會實際改變成果的缺項，將相關問題合併；等待答覆時繼續參考分析或工具檢查。不要求逐階段批准，除非使用者要求審稿。
2. **建立本書來源。** 新書從需求模板填寫 `brief.json`，記錄明示要求與自行判斷的選擇。模板故意留空，不是預設故事。可用 `init_book.py` 檢查需求並建立不覆寫既有書的草稿目錄；它不會生成插畫或成品。
3. **細讀參考。** 實際查看參考 PDF 的所有頁面縮圖與關鍵高解析畫面，分析文字、鏡頭、留白、配色、反覆句和翻頁動機。記錄可採用的通用技巧及新作如何轉化，不複製人物、構圖或原文。
4. **完成故事與分鏡。** 依年齡、閱讀方式和內容任務調整句長、字量、概念及圖文分工。先形成完整故事，再分配跨頁與翻頁鉤子；學習目標融入情節，不把故事寫成生字清單。先核對字形、詞義、部首及知識，再進行大量插畫。
5. **建立角色與美術設定。** 為本書建立角色模型表、服裝與道具規則、配色、媒材及留白方案。使用可用的影像生成／編輯工具製作插畫，以本書模型表維持一致。保存原圖、精確提示、參考、修訂與雜湊。模型圖不承擔精確漢字排版。
6. **以原生文字排版。** 故事、字目、姓名、頁碼和活動文字使用可編輯文字；插畫保留為獨立圖像。依本書設定處理字型、強調字及專名號，以實際字型度量定位，不以等寬假設或手工描字取代。所有輸出由同一份故事／版面資料產生。
7. **完成指定成品。** 產生要求的單頁／跨頁 PDF、可編輯檔及來源。頁數、尺寸、封面、扉頁、活動頁和製作頁按本書設定計算，不能套用固定 18 畫面或 34 頁。只有要求點讀時，才加入音檔、點擊映射及書架註冊。
8. **驗證實際檔案。** 核對原稿、PDF 可見文字與嵌字、可編輯文字／字型／字級、單頁裁切、中縫、角色及圖文關係；實際渲染全書並用辦公／向量工具開啟代表頁。遇到缺字、裁字、文字蓋圖或圖文矛盾，修正後再輸出。
9. **保存與交付。** 按專案規則建立每個可審閱階段的 Git commit。已有 GitHub／網站發布授權時，推送、等候發布，再核對永久網址的實際內容；沒有此授權的其他專案先交付成品，不自行對外發布。最後提供成品連結、驗證結果及存檔點。

## 必須保持的界線

- 年齡、主題、故事、角色姓名、語言、書名、篇幅、字目及排版參數不是固定值。7–9 歲、犬／走部、琪琪／樂樂、14 個故事跨頁均只是過往案例。
- 當次使用者要求優先。新書不沿用上一冊的角色、插畫、情節或教學目標；同一本書修訂則保留已接受內容及原圖，避免無關重製。
- 原始附件、插畫、字型授權與可編輯來源須保留；是否公開參考附件依使用者要求與專案規則處理，不把參考書當成新作素材發布。
- 不把整頁點陣圖放進 PowerPoint 後稱為可編輯排版；說清楚文字、圖像與向量物件各能編輯到甚麼程度。
- 不把缺字替代、假時間軸、假音檔、未生成頁面或內部校稿佔位內容當成完成品。
- 此 repository 的 GitHub、點讀音源與發布規則以根目錄 `AGENTS.md` 為準；其他專案不得無條件套用此站的網址、聲音或部署指令。

## 完成檢查

交付前確認：需求有來源、故事與年齡相符、插畫連貫、文字可讀、格式齊全、來源可編輯、實際檔案已驗證、Git 已存檔。要求網站發布時，再確認永久網址回傳的是此次驗證的檔案。將尚未通過的項目如實說明，不以推送成功代替出版完成。
