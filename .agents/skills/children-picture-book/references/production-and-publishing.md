# 輸出、點讀、存檔與發布

## 專案與工具

建議每書有需求表、故事來源、設計分析、角色／插畫原圖、精確生成紀錄、字型授權、排版程式、可編輯檔、成品、驗證紀錄及 README。臨時渲染和快取不冒充正式來源，依專案規則忽略。

本 repository 可參考：

- `books/lets-find-that-cloud/build_book.py`：共用版面、實際字型度量、姓名專名號、PDF／PPTX／SVG、逐頁文字／幾何驗證。
- `books/little-wolf-your-turn/build_reader.py`：圖像頁面與逐字點擊矩形、讀音映射、尚未上架的點讀 manifest。
- `scripts/generate_audio.py`：驗證快取、有限重試、真正音檔與時間、完成後才原子更新書架。
- `.github/workflows/publish-site.yml`、`scripts/check_live_site.mjs`：提交、驗證、同步 Pages 和線上內容雜湊。

路徑以 repository 根目錄解析。這些是特定書的已驗證範例，**不是通用建書引擎**。重用時先移除固定書名、slug、角色、字目、頁數、尺寸、字卡、詞庫、檔名及書架斷言；逐個確認都取自本書資料。不要直接執行舊書 builder 覆寫已出版成品。

依實際工具需求固定依賴版本，在工作區虛擬環境安裝；不要為只是製作 PDF 的工作安裝整套語音模型。若工具或網絡受限，採可用的替代製作／驗證方法，如實記錄尚未完成的格式，不交付假的成品。

## PDF 與可編輯檔

依需求輸出單頁或跨頁 PDF，清楚計算封面、扉頁、內頁、活動及封底。單頁拆分逐頁核對實際可見文字和中縫裁切，不能只除以二計算頁數。

可編輯交付必須有原生文字、獨立圖片及可編輯線條／色塊。PNG 插圖可獨立替換不等於可逐筆編輯；只有真實向量才稱為向量插畫。SVG 外連圖像時保留相對路徑與 assets，PowerPoint 字型未嵌入時附字型安裝指引。要求 EPUB／HTML 時另行製作與實際開啟，不把 PDF 改副檔名當作交付。

輸出驗證至少涵蓋：

1. 逐頁文字符合本書核准的故事來源；修訂後沒有舊姓名或舊句子殘留。
2. PDF 實際使用／嵌入字型、缺字、字級與字目比例；單頁裁切、中縫、標點與換行。
3. PPTX／SVG 仍有原生文字，字型、粗細、位置和線條符合共用版面；專名號每個姓名都有。
4. 插畫及字型來源雜湊、角色連貫、道具數量、圖文與知識正確。
5. 所有頁面的渲染與代表頁的實際 Office／SVG 開啟；記錄工具、結果及限制。

實體印刷需要另做出血、色彩、解析度和印廠規格；數位檔驗證不能直接宣稱已適合印廠製版。

## 另有要求才製作粵語點讀

圖書成品不自動等於已上架的點讀書。使用者只要求 PDF／可編輯檔時，完成那些成品即可；要求點讀時，再製作頁圖、句子／詞語／單字、讀音、音檔及播放同步。

在點點書房，遵守當前 `AGENTS.md`：`edge-tts`、`zh-HK-HiuMaanNeural`、`-12%`，保存實際 WordBoundary。引擎版本以鎖檔及實際生成紀錄為準。其他語言或新的聲音要求以本次設定為準，不能把舊聲音重新標示成新音源。

姓名、多音字及部首符號需要實際試聽；顯示文字與朗讀文字不同時建立明確映射。字級不一時每個字使用真實矩形；逐詞／逐字提示跟隨真實音訊時間，不均分時長，不讓亮光遮擋筆畫。

本專案的粵語正音依香港中文大學《漢語多功能字庫》，逐字記錄來源、按實際詞義選讀音，姓名和部首名稱另列。字庫候選讀音、上下文選音及生成聲音的正音聽校是不同步驟；不能把字庫查詢成功或 ASR 轉寫成功當成所有聲調已正確。相同字形在不同語境讀法不同時，音檔識別需含讀音／語境，不能只按單字文字去重。

全部音訊生成、解碼、雜湊及對齊完成後才註冊書架。網絡或語音服務失敗時保留已發布的索引和音檔；先保存已驗證生成成果，再執行較長的瀏覽器測試。

實際測試每頁三種點讀、暫停／繼續、重播、停止、跳播、語速、跨頁、箭頭／滑動、放大及窄螢幕。另核對姓名／放大字／符號的點擊與時間映射。

## Git 與永久網站

遵循所在專案 `AGENTS.md`。本專案已要求 GitHub 保存全部正式檔案、每階段 commit、驗證後同步永久網站，因此在授權範圍內直接完成，不反覆請求已取得的確認。其他專案依其使用者要求決定是否公開。

可審閱的階段通常是需求／故事、美術／版面、完成驗證／發布；按實際工作規模設存檔點，不為湊數製造空提交。保留歷史與原始資產，禁止強推覆蓋別人的修改。

發布新增／修改下載品時，將其加入永久網址內容雜湊檢查。根據修改範圍執行必要驗證；本專案的重要檢查為 `npm test`、`python3 scripts/validate_assets.py --require-edge` 及實際網站檢查。純文件／skill 更新不需重新生成舊插畫或音訊。

推送 `main` 後等候自動流程：正式檔案同步 `gh-pages`、精確提交的 Pages 建置成功、永久網址的檔案 SHA-256 與 Git 版本一致、實際閱讀驗證成功。相同 SHA 有重複建置時，不把被取代／取消的一次當成最終結果；在有限等待內確認最新建置，持續失敗則定位並修復，不宣稱發布成功。

完成回覆簡短列出改動、可用成品、驗證結果與 commit；有未完成項就說明具體限制，避免把僅有草稿或本機檔案說成已出版。
